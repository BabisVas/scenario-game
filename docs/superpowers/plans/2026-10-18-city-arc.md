# City Arc (Part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the ten objective-style scenarios with a five-scenario city arc of situations, and add the systems that fill the city: time of day, worlds, sponsor selections, companions, survivor groups, zone encounters and live events.

**Architecture:** Every new rule is a pure engine module in `src/engine/` that takes `GameState`, `rng` and `content` and returns a `Step`, as now. Two shared data vocabularies carry most of the new content: **conditions** (when something may happen) and **effects** (what it does), each validated by `src/data/validate.ts` like choice outcomes are today. Scenarios gain new goal kinds and engine-enforced loopholes; all scenario, encounter, event and companion text lives in `src/data/`.

**Tech Stack:** Vite, React 18, TypeScript (strict), Vitest, React Testing Library, plain CSS, GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-10-18-city-arc-design.md` (builds on `docs/superpowers/specs/2026-10-10-scenario-game-design.md`; rules decided since live in `CLAUDE.md`, `docs/HANDOFF.md` and the ledger `.superpowers/sdd/2026-10-10-scenario-game/progress.md`).

## Global Constraints

- Permadeath, one long life, nothing carried between games.
- Original world; placeholders `«CITY»`, `«SYSTEM»`, `«ANNOUNCER»` defined once in `src/data/names.ts`.
- All player-facing text is written with the abyssal-epic-style skill in Browser Game mode: short blocks, phone-sized, second person present, system messages in brackets and always true.
- Babis never sees content. Status reports to him are spoiler-free; content goes to his reviewer through `docs/content/city-arc-draft.md`. Commit messages for content stay generic.
- Nothing bad can happen while the tab is closed: catch-up may move survivors, groups and live events, and never damages the player or a companion, spends scenario hours, fails a scenario, or kills a survivor a scenario depends on.
- Scenario clocks run only on in-game hours spent by player actions.
- Engine code never imports React, never reads `Date.now()`, never calls `Math.random()`.
- Save rules in `CLAUDE.md` ("Saves") apply: one new save version (4) for the whole plan, a 3→4 migration, recorded fixtures; content-only changes never bump the version.
- Playable at 375 px wide and on desktop.
- Superseded by the new spec: "the player fights alone in v1" and "contract offer at interest 60".
- Anti-goals from the spec are requirements: every loophole the rules state is enforced by the engine; every betrayal is preceded by warning signs; companions have a voice; encounters are short; the proof scenario is not "kill a living thing within a time limit"; nothing is copied from the novel.

## Review Focus

1. **A live v3 save (Babis's) caught mid-old-scenario, mid-fight or mid-choice** must load into the rest period before the mapped new scenario, keep character, inventory, survivors, constellations and active contracts, and play on. Test in Task 18.
2. **Tab closed with companions, groups and open live events**: catch-up resolves events by default and may reshape groups, but never touches the player or a companion, and never removes a companion from the party. Tests in Tasks 6, 10 and 12.
3. **One survivor in two roles** (a companion who is also in a choice group, the ward, a live-event participant or a group leader): each system must agree who they are; a companion is never a live-event participant, is culled like anyone else in a choice group (and then dies as a companion), and can never be the ward. Tests in Tasks 6, 9 and 12.
4. **The catastrophe's route meets a sealed zone or the zone the player stands in**: it skips sealed zones, damages the zone it enters, and kills survivors there but never the player's party by itself. Test in Task 17.
5. **Two things want the single `pendingChoice` slot** (a selection while an encounter is open, an encounter while a contract or scenario choice is pending): nothing overwrites a pending choice; a blocked selection opens as soon as the slot frees. Tests in Tasks 5 and 10.

## How this plan runs

- **Branch.** Work on a branch `city-arc` in a worktree (superpowers:using-git-worktrees). `main` deploys to the live game Babis is playing; nothing merges to `main` before Task 23's STOP.
- **Save version 4 while unreleased.** Task 1 bumps `SCHEMA_VERSION` to 4 and creates `MIGRATIONS[3]`. Every later task that changes `GameState` extends `MIGRATIONS[3]` with its defaults, then deletes `src/save/fixtures/save-v4.json` and `shape-v4.json` and reruns `npm run save:fixtures`. This is allowed only because v4 has not shipped; `save-v3.json`/`shape-v3.json` are never touched. Each such task's verification includes `npx vitest run src/save`.
- **Order and the catastrophe STOP.** Build Tasks 1–16, then 18 and 19 (migration and UI pass do not depend on the catastrophe). Then **STOP** and tell Babis you are at the catastrophe. Task 17 starts when his rules arrive, and the content draft (Task 20) follows Task 17.
- **Context.** When the session's context gets high (around 70%), write `docs/HANDOFF.md` the way the last handoff was written, and tell Babis so he can start a fresh session.
- **Content is the builder's.** Engine tasks use fixture content in tests. Real content arrives in Task 20 (draft, STOP) and Task 21 (data files).
- **Ledger.** Continue `.superpowers/sdd/2026-10-10-scenario-game/progress.md` style in a new workspace for this plan (`sdd-workspace` on this plan file).

### Task 7: Companions II: fighting beside you

**Files:**
- Create: `src/engine/companionCombat.ts`

**Interfaces:**

It runs after the player's action and before the enemy acts. `guard` adds to the player's `braced` armor this round; `stun` makes the enemy skip its turn, using the existing stun path.
  - `pickTarget(state: GameState, rng: Rng): 'player' | string`: weights are player 2, aggressive companion 1, careful companion 0.5.

  - ruthless: attacks, ×1.5 damage if the enemy is at ≤30% HP;

### Task 16: War between groups

- Every group's `warScore` resets to 0 at start.
- **The player's actions decide the war, not dice.** The score sources (config values), all applied on the player's spent hours or actions, never on world ticks:
  - **chance:** each group gains 1 with chance 0.3 per in-game hour (`WAR_DRIFT_CHANCE`), and that is all the dice do;

- At clock end the highest score wins (ties: the player's side loses the tie).
- Player on the winning side → clear. On a losing side → death if `loseIsDeath`, else a rest period with no reward. In no group → clear with no coin reward, after applying `neutralEffects` (staying out has its cost).
